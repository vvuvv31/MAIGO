# Step 09: 生产级综合集成测试套件建设

## 1. 目标与背景

前述步骤已经实现了生产路径的物理逻辑加固。在进行大规模 GPU 模拟之前，必须在单元测试框架中建立一套端到端调用真实 `transport_sycl()` 的集成测试，杜绝“仅单测 runner 没测主干”的问题。

本步骤必须：
在 `tests/carbon_tests.cpp` 中增加系统性的集成测试，验证生产主程序在各种物理场景下的正确性与鲁棒性。

## 2. 涉及文件

- 修改/增加：`tests/carbon_tests.cpp`
- 测试数据准备：`config/test_*.yaml`

## 3. 详细技术规范

测试必须涵盖以下 7 大维度：

1. **Water / Schneider CT 双路径路由测试**：
   - 无 CT 网格配置 -> 模式确定为 `Water`。
   - 提供有效 CT 网格 -> 模式确定为 `SchneiderCt`。
   - 提供 CT 网格但缺失 Schneider 数据文件 -> 提交 GPU 前抛出明确异常。
   - 验证生产 CT 路径绝对不会调用任何四分类转换函数。
2. **水物理回归严格保护测试**：
   - 固定随机数种子，对比修改前后的水介质能量沉积、射程、横向离散度，确认数值绝对不变。
   - 无论磁盘上是否存在 Schneider 文件，水物理输出结果完全不受干扰。
3. **CT 生产路径集成真实调用测试**：
   - 真实调用生产入口 `transport_sycl()`。
   - 验证当体素 section 改变时，停止功率、MCS 与核反应率立即同步改变。
   - 验证密度 $\rho$
ho$\rho$ 在核反应率与能损计算中仅被单次相乘。
   - 验证初级碰撞目标核严格来自 13 偏反应率抽样。
   - 验证次级碰撞目标核完全独立于初级碰撞。
   - 验证 C、N、Ca 等重目标核绝不会被 alias 到 O。
4. **缺失数据 Fail-Closed 拦截测试**：
   - 人为在包中挖空某能量节点或某目标核，验证生产程序报错退出，不静默运行。
5. **SecondaryRateTable 畸变数据全覆盖测试**：
   - 运行 Step 07 构造的畸变二进制文件测试集。
6. **CINEL03 边界防护测试**：
   - 运行 Step 08 构造的溢出与越界测试集。
7. **验证器回归测试**：
   - 验证 Step 00 编写的 `verify_step20_validation.py` 在 12 pass + 1 fail 时整体判定为 FAIL。

## 4. 验收标准

1. 构建系统成功编译所有测试目标：`cmake --build build -j 16 --target carbon_tests`。
2. `ctest -R carbon_tests` 测试 100% 通过。
3. 无内存泄露，无未初始化读取。
