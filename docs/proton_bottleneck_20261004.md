# 当前 proton minibeam 吞吐瓶颈

分析对象为最新完成的 RT07575 0.1% full plan：236,086,432 primary、487 spots、119 批单进程，RTX2080Ti，group32、全 FP32 独立电子输运和剂量计分。此轮只分析已有完整日志及硬件剖析，没有新增性能候选或更改运行代码。

## 实测耗时

完整墙钟 2178.596 s，平均每批约 198.4 万 primary、18.31 s，含加载吞吐 108,366/s，驻留吞吐 108,716/s。

| 互斥计时类别 | 全计划累计 | 每批均值 | 墙钟占比 |
|---|---:|---:|---:|
| 电子队列 kernel | 956.43 s | 8.04 s | 43.90% |
| 铜 / 空气主粒子 kernel | 561.27 s | 4.72 s | 25.76% |
| CT 主粒子 kernel | 413.20 s | 3.47 s | 18.97% |
| 输运循环剩余时间 | 120.29 s | 1.01 s | 5.52% |
| 每批准备（含首次加载） | 99.96 s | 0.84 s | 4.59% |
| 读回及 host finalize | 10.77 s | 0.09 s | 0.49% |
| quality 和输出 | 10.47 s | 0.09 s | 0.48% |
| 其余未归类墙钟 | 约 6.21 s | 约 0.05 s | 0.29% |

前三项来自 GPU event 累计，输运循环剩余为该循环 wall scope 减前三项，包含次级粒子、调度与传输等，不能全部归为 CPU 开销。准备/读回/输出使用独立 scope；未把它们和包含这些阶段的 transport_total 再相加。首次 transport setup 为 6.73 s，且包含除电子包以外的准备，不能全部叫电子包读取时间。

**电子是最大单项，主粒子输运合计也有 44.73%。** 减少磁盘包体积、增加一次加载后的批次数，对这次已经119批复用的长作业帮助有限；输出仅约0.5%。

## 电子执行限制

同一正式二进制的 NCU 完整网格单 launch 参考证据：block256、grid64，共16384 lanes。每条 warp 指令平均执行线程7.96/32、活跃warp占峰值24.84%、每线程248寄存器、静态栈1392B、long-scoreboard43.57%，local load/store分别约39.18亿/30.82亿sectors。这些是一个代表性launch的诊断，不是全计划平均；local请求不能全当DRAM流量或唯一spill因果证据，7.96/32也不是整卡GPU利用率。

证据支持优先检查分支分歧、大量活跃状态和依赖访存延迟。worker 同时处理 birth、joint、charged、photon、计分和异常记录，并保留 task、packet、previous 等状态；动态变量/指令级归因尚未完成，不能只凭源代码指定唯一罪魁。

完整 full plan 实际执行 782.97 亿次 charged 调用，其中599.36亿次弹性事件（76.55%）；另有192.43亿次 joint advances。此前与当前物理路径一致的两批 FP32 诊断表明，约68.44%的 charged 调用在10–100 keV；约80%步长由碰撞飞行限制、19%由平均能损限制，最大步长上限触发约0.25%。直方图来自此前诊断版本，不是重新对119批采样的结果。

因此需要优化的主要是大量低中能电子短步的执行成本。单独放宽0.05mm最大步长不能据此推断显著加速，且仍须遵守minibeam空间剂量要求。

## 主粒子部分

铜/空气4.72s/批比CT3.47s/批还大。早期 RT07575 主核剖析显示255寄存器、约24%warp占用、显著依赖访存与指令供给等待，DRAM吞吐仅峰值13–21%。这些是旧packed阶段的诊断，当前主粒子耗时仍接近，但不能把旧硬件百分比冒充新二进制的完整剖析。

继续优化需要用当前二进制分别确认铜/空气和CT主核的活跃状态、local-memory指令热点及等待来源。只提高电子部分会逐渐受这8.19s/批的主粒子成本限制。

## 收益量级与下一步优先级

在其他耗时不变的理想模型下，按本次实测全计划时间计算：

| 假设 | 预计完整吞吐 |
|---|---:|
| 电子阶段加速2倍 | 约13.88万 primary/s |
| 电子阶段加速4倍 | 约16.16万 primary/s |
| 主粒子阶段加速2倍 | 约13.96万 primary/s |
| 电子和主粒子均加速2倍 | 约19.46万 primary/s |

这些是收益上限估算，不是新测试。若完全不改善其他部分，仅靠电子达到18万/s，需要电子累计时间从956.43s降到约89.42s，即约10.70倍加速。

建议先做当前电子kernel的源级/local-memory热点归因，缩小必须常驻的状态；同时更新铜/空气主核硬件剖析，以当前约26%整轮占比确定主粒子侧优先级。后续结构变化须同时降低状态交换/访存开销并改善有效执行线程，不能只以减少调用次数或提高活跃线程为成功标准。

已经查过 `failed.md`：合并弹性段虽减少47% charged调用，却未提高吞吐并恶化local访问/活跃线程；两阶段electron worker因往返和状态交换变慢；worker生命周期累积8个审计计数曾显著变慢；inverse-CDF运行时和速率多项式未证明收益。不能原样重试这些路线。更大步长、局部沉积或减少光子也不能作为无验证的吞吐捷径。

优先级为 **电子执行状态/分歧与访存 → 铜/空气主输运 → CT主输运 → 批次准备**。本轮没有新候选被否决，因此没有新增失败路线记录。
