# 硬碰撞速率多项式求值筛选

没有接入正式运行路径。CPU/GPU数值检查通过，但孤立查表计时没有可分辨收益。
正式程序保持已验收的体素缓存版本，约111k primary/s、电子阶段7.79s/批。

原生四个采样点对应同一个三次插值多项式；新表示在加载时用已转换为FP32的
原采样值计算以`t−0.5`为变量的四个系数，运行时使用三个FP32 FMA。
原速率上界、能量区间、原始包和碰撞过程不变。初版无保护转换在近零点产生
38个正负号变化，已经否决并存档。

修正版对64个子区间做向外舍入的区间求值，仅在多项式下界大于原采样值最大
绝对值的1%时转换，否则保留原Lagrange公式；没有将小速率归零。
9339个区间转换，2830个保留原公式。额外标志令记录由24B变为28B。
原始域检查仍执行，新公式另有连续区间上界检查，最大上界/原majorant为0.166897。

82节点、12169区间，每区间4097个表示能量，共49856393点。CPU与GPU各检查
一遍：零无效、零正负号变化。最大绝对速率差为原majorant的1.158e-7；
参考绝对速率大于majorant的1e-6时，最大相对差约7.147e-6。
CPU另以long double求值同一FP32采样点的精确多项式作独立数值对照。
这些是分量检查，不是CT剂量验收。

RTX2080Ti孤立查表测试包含运行时二分查找及新记录布局，能量在覆盖范围内
按对数均匀抽取，节点/过程均匀分布；不是实际CT轨迹加权分布。
每次16777216查询，预热后每轮按ABBA顺序，三轮候选/参考耗时比：
0.99725、1.00683、0.99848，均约3.46ms。没有证明有用的加速，故未进一步
改动正式路径或进行整批计时；也不据此声称整批必然变慢。

当前实际硬碰撞提议只占charged调用约3.33%，该公式还受查找和访问成本影响。
后续重试需要新的查找/布局设计或有代表性的运行时成本证据。
