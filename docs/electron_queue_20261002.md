# CT 电子包每步补充任务优化（2026-10-02）

当前 RTX 2080 Ti 的 proton CT minibeam，采用每个持久循环迭代执行一个电子事务、已完成线程及时领取下个任务的调度。两组独立种子、反向顺序、每臂每次 200 万入射粒子确认：**电子吞吐 +7.02%，输运吞吐 +2.20%，完整吞吐 +0.88%**。这是小幅端到端收益，不是物理模型简化。

## 实现

改动仅在 `src/transport_sycl.cpp` 的 queued material-electron 主循环。原先每个线程领取任务后，在内层循环输运到终态，再回到外层取任务。现在把任务绑定、单步推进和终态计分放入同一个外层循环；活跃包每次推进一个事务，结束的线程在下一轮取任务，减少等待长轨迹的空闲。

- 每个任务仍携带原来的独立 RNG、权重、出生状态和材料编号；所有抽样、原始响应库、逐路径材料/边界处理与横向沉积保留。
- 原来的 4096 次事务上限、出生失败处理、完整 `previous` 故障快照、能量汇和审计全部保留；未对活跃包做局部沉积或轨迹截断。
- 不新增续跑状态队列、排序或每步 kernel launch。任务仍为 128 bytes，576 MiB 队列容量 4,718,592；group32、chunk262144、lanes16384、tiered_decoded 和热数据预算均不变。
- 所有构建与 GPU 计分固定 `CARBON_DOSE_FP32=ON`、`CARBON_DOSE_FP64=OFF`。

## 独立性能确认

种子 100230201 按原版→新版，100230202 按新版→原版运行，每次 200 万历史；所有编译和 NCU 剖析均与计时分离，普通 GPU 运行串行。正式吞吐只使用以下四次普通运行，未计入筛选或 NCU 重放时间。

| 指标 | 原版均值 | 新版均值 | 吞吐变化 |
|---|---:|---:|---:|
| 电子队列 | 9.0020 s | 8.4114 s | +7.02% |
| 输运 | 25.8258 s | 25.2708 s | +2.20% |
| 完整运行 | 47.8921 s | 47.4720 s | +0.88% |

完整吞吐约 41761 → 42130 histories/s。电子耗时减少约 6.56%；“吞吐增加”和“耗时减少”的分母不同。两对完整吞吐分别 +0.745% / +1.025%，电子吞吐分别 +6.800% / +7.242%。完整运行仍包含约 22 秒的初始化和其他处理，因此电子核收益被稀释。

结果仅覆盖当前 CT、源和 RTX 2080 Ti；本轮没有复测 L4、碳 CT 或 broadbeam 吞吐，不把 CT 电子改动外推成其他场景加速。

## 硬件证据

利用已有授权的 ps/sudo 会话运行 NCU，没有修改全局驱动权限。基线与新版都使用 300k 历史、相同种子 100230001，选取第一次电子队列 kernel（对应首个 262144 历史批次）。以下为单次 kernel 诊断，不是整次运行的全局平均，也不使用 profiler 的估计加速作为实测收益。

| 指标 | 原版 | 每步补充任务 |
|---|---:|---:|
| 平均活跃线程/warp | 4.40 / 32 | 8.26 / 32 |
| Eligible warps / scheduler | 0.04 | 0.03 |
| Long-scoreboard 等待占平均指令间隔 | 约 75.3% | 约 77.5% |
| L2 hit rate | 85.30% | 85.46% |
| DRAM 利用率 | 24.66% | 16.10% |
| 每线程寄存器 | 255 | 255 |
| 静态栈 | 2640 bytes | 2688 bytes |

线程活跃度提高，但内存依赖等待仍突出，静态栈略增，occupancy 仍受寄存器限制；不能声称解决了 spill、消除了访存等待或提高了可发射 warp 数。原版 64 个 block / 68 个 SM 的未覆盖现象也没有自动转化为调参收益，见下面独立否决结果。静态资源提取还确认全部 primary kernel 的资源声明一致，这不是其他场景性能测试。

## 正确性与回归

两组主确认的离散输运/EM审计、电子 tasks/advances/source restarts/boundary restarts 完全一致。最大剂量相对 L1 为 5.072e-8；所有非零体素最大局部相对变化为 2.134e-6，即 **0.000214%**；没有新增/丢失非零体素。分深度峰谷 ROI 最大相对变化 9.856e-10。最大相对能量残差 3.795e-7，队列溢出为 0。

另完成以下匹配回归，质量、能量、离散计数和局部剂量检查均通过：

- Group1 高水位：16384 入射历史，4,247,129 个任务，27,901,491 次推进，6,748,822 次边界重启；两版完全一致，原队列容量下零溢出。
- 关闭延后出生采样：100k 历史，849,883 个任务和 5,487,657 次推进完全一致；日志确认 `CARBON_CT_DEFER_BIRTH_SAMPLING=0` 实际生效。
- 水 minibeam：1M 历史；离散审计一致，剂量相对 L1 1.851e-7，最大局部变化约 0.000223%。这仅为回归，不宣称水吞吐改善。

这里验证的是既有研究模型的实现等价性；没有重新跑 TOPAS、改变 Water_75eV 参考，或解除 group32 / 材料电子响应原有的物理验证限制。

## 未采用的候选

实验前搜索 failed.md；新路线及其依据保存在 notes.md，以下已追加到失败台账。

1. 延后故障快照：正常路径不保存 previous 整包，第一次失败后单独重放诊断。静态栈 2640→2304 bytes，但 1M 基线/候选/基线完整时间 35.7350/35.6827/35.8908 s，电子 4.44264/4.37475/4.49945 s；约 0.36% 完整收益未充分分辨，未采用，也未声称完成强制失败重放验证。
2. 补齐 68 个 SM：同一 refill 二进制，16384/17408/16384 lanes 的 1M 完整时间 35.0965/34.9374/35.0617 s，电子 4.19176/4.23391/4.20735 s。电子反而约慢 0.82%，没有确认有用净增益；保留 16384。仅显式允许 queue_lanes 配置元数据差异，真实审计和队列检查未放宽。
