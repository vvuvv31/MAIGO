# Proton CT minibeam 吞吐优化（2026-10-01）

本轮目标是在保留物理模型的条件下提高 CT minibeam 吞吐。
用户允许关键峰/谷区域额外剂量变化约 1% 以内，并要求检查局部差异。
当前候选保持物理模型、步长和电子 group32 不变，按更严格的整数输运/EM审计一致性验收。
GPU 为 RTX 2080 Ti，FP32 dose ON / FP64 OFF，Water_75eV，stopping scale 1.0。

## 数据常驻与批量运行

现有 `material_electron_retain_bank` 需要同一进程内的 context 才能复用。
新增 `scripts/run_ct_batch.py` 生成隔离配置和 manifest，调用已有单进程批次入口，
记录二进制/config SHA、实际历史数、完整墙钟及各批 quality。
不会把独立进程间操作系统文件缓存命中误认为设备电子响应表缓存命中。

优化前二进制、3×2M同进程：完整239.084秒；每批93.765/72.185/72.061秒；
初始化23.788/1.547/1.340秒，电子表缓存2次命中。
与此前相同种子的独立进程结果相比，整数审计精确一致，剂量L1≤4.27e-9。
这组基线缓存测量与CPU候选编译重叠；没有并发GPU任务，不能用于微小性能变化归因。
批处理属于已有缓存能力的可复用运行入口，不是新的主输运算法。

## 候选一：严格准入的 CT 主内核专用化

新增stage11，复用原material-aware stage4的物理主体；仅将host已经验证的20个参数替换为编译期常量。
包括proton物种、Urban、CT几何、材料电子队列以及关闭的水/insert/诊断替代路径。
所有采样、步长、核反应、评分和质量门槛保持原样。
满足条件默认开启；`CARBON_CT_QUEUED_PRIMARY_SPECIALIZE=0` 可运行原stage4对照；
显式设1对不符合条件的配置报错，默认则保留原路径。

相同二进制、两组独立2M种子、反向执行顺序：完整平均91.728→82.976秒，
吞吐+10.55%，患者主核吞吐+24.68%。
另两组独立2M，直接对照优化前二进制：平均92.328→83.099秒，吞吐+11.11%；
两对分别+10.60%/+11.61%。
静态栈7712→4192字节/线程，均为255 registers；静态资源不等价于运行时spill/stall诊断。
默认开关调整前后的整个CUDA device image逐字节一致。

10k入口相空间逐字节一致，所有CT对照整数审计一致；已测逐非零体素最大相对差异约5.45e-7，
显著低于1%的剂量预算。深度0–20/20–80/80–120/120–180/180–230/230–303.5mm的峰/谷积分另存。
峰ROI定义为|x|≤15mm、距3.6mm狭缝中心≤0.25mm、|y|≤15mm；谷ROI距最近中心≥1.55mm。
原研究模式和既有物理近似标记保留，没有新增TOPAS准确度认证。

水模体2×4M对照完整吞吐变化−2.58%/+0.16%，汇总−1.20%；整数审计通过、剂量L1≤1.85e-7。
这组结果不支持水路径加速，也不足以对百分之一级变化作硬件归因。
碳10k入口相空间及整数审计通过，剂量L1=4.93e-8。

## 候选二：电子出生轨迹抽样延后

原CT每个EM步骤为两个密度端点抽取birth CDF，随后group32只保留一个加权代表任务。
新候选逐步执行原材料/密度/能区/通道支持检查，保留原fraction、weight和reservoir抽样；
将保留任务的birth CDF抽样移至已有电子队列。保存原energy与birth随机数，
队列后续随机数状态不变，出生点、方向和混合后的fraction不变。
初版任务从128增加为144字节，虽有收益，但会在同一576MiB预算下减少队列容量，已否决该布局并记录于failed.md。
有效group1基线16384历史产生4,385,915个任务，超过144字节布局的4,194,304容量。
最终通过重排原birth/reference的全部字段，利用原有对齐空隙保存energy和uniform；
没有截断任何字段，也没有非对齐packed访问。任务恢复128字节，容量保持4,718,592，
并增加编译期大小断言及全部字段的逐位序列化回归。
最终group1相同16384历史完成4,385,915个任务，推进28,897,258次、边界重启7,024,423次，
均与原版一致；溢出0，剂量L1=4.72e-9。

这是minibeam材料出生分布+现有group32队列的执行布局变化，
不同于failed.md中宽束inline joint-response仅延后endpoint CDF的失败方案。
新实现不提高group size，不改变有限电子轨迹库，不做剂量缩放。
GCC及项目Clang分别通过1,109,850个prepared/resolved与原sampler的逐位对照，
含边界、密度混合、空通道、无效输入，以及最终布局全部字段的无损还原。
初版144字节布局的两组2M同二进制对照为+4.92%/+5.37%，合计+5.15%。
该数字只用于筛选机制，不作为最终128字节交付版本的独立增益；最终版本以下面的直接对照为准。
`CARBON_CT_DEFER_BIRTH_SAMPLING=0` 可关闭延后抽样；默认仅对proton CT minibeam电子队列启用。

全部原始证据、源码快照和构建日志位于 `out/ct_opt_20261001/`。
