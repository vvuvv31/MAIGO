L4 在 broadbeam 上得到较明显的吞吐提升。Minibeam 的 primary 更快，但电子阶段变慢，且 Colab 初始化显著慢于本地，所以 200 万粒子的整次运行更慢。这是 Colab 系统与本地主机的实测差异，CPU、驱动和 PCIe 均不同，不能全部归因于 GPU 核心。

两端保留 tiered/host_mapped 响应配置：2 GiB 热数据预算、实际 hot_device_bytes=2077906392，bulk 中仍有 3456260184 bytes 走映射主机内存。L4 的额外显存未用于扩充该预算。本次没有测试全驻留或 L4 专用缓存调优；现有计时不足以单独证明电子变慢的具体硬件原因。

复现与解释范围：

- Proton broadbeam：`config/proton_ct_plan_fe.yaml`，RT07575 CT 的 `part_01/spots.csv`，12,531,500 histories，并非完整多分区计划。
- Carbon broadbeam：`config/carbon_ct_plan_fe_joint.yaml`，RT07575 CT，6,481,909 histories，保留 joint electron response 研究配置。
- Proton minibeam：`config/proton_ct_minibeam.yaml`，lung CT、170 MeV、原有铜准直器，每次 2,000,000 histories。
- 这三个预设本身的物理近似不同：proton broadbeam 为局部电子沉积，carbon 为 joint response，proton minibeam 为材料电子空间响应。本报告只比较每个预设在两卡上的性能，不把三者的吞吐差异解释成单一粒子种类效应。
- 两卡运行相同 SHA256 二进制 `d04b5c130fb98b69b35aea305b2672306cd697a1a4d7375fca1dcdee7c72d04a`，`CARBON_DOSE_FP32=ON`、`CARBON_DOSE_FP64=OFF`。所有配对配置 hash 相同，远端所有输入 hash 已校验。
- L4：Colab，23,034 MiB framebuffer，72 W 上限，驱动 580.82.07，PCIe 链路上限报告 Gen3 ×16，12 vCPU / 约 53 GiB 主存。本地：RTX 2080 Ti，驱动 560.35.05，AMD EPYC 9965 主机。完整硬件信息保存在 evidence 目录。
- L4 首个 50,000 histories 预热耗时 647.644 秒（其中输运计时 640.433 秒）；期间 CPU 满一个核、GPU 空闲且已加载 PTX JIT 编译库，符合首次驱动编译开销。没有成功取得编译调用栈或单独 JIT 计时，因此不将整个预热时长等同于纯编译时间。后续重复正常，预热完全排除。
- 本地三算例交错并在第二轮反转；远端先完成 broadbeam 交错重复，再运行 minibeam。每次都是独立进程。
