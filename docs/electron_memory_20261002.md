# CT 电子包显存分配优化（2026-10-02）

RTX 2080 Ti、proton CT minibeam，两组独立种子、反向顺序、每次每臂 200 万历史确认：**电子吞吐 +73.63%，输运吞吐 +16.53%，完整吞吐 +9.95%**。有效改动是当前 CT 预设的显存分配；输运源码和正式二进制保持上一轮每事务及时补充任务版本，物理模型与随机数不变。

## 改动及原因

`config/proton_ct_minibeam.yaml` 两项参数：

| 参数 | 原值 | 新值 |
|---|---:|---:|
| `secondary_queue_capacity` | 隐式默认 32,000,000 | 显式 8,000,000 |
| `material_electron_response_hot_device_budget_MiB` | 2048 | 4096 |

原配置为患者次级粒子队列和铜级联队列分别预留 3200 万条目，合计约 3.34 GiB。改为各 800 万后释放约 2.50 GiB，用于容纳完整的预解码响应记录和既有热数据。原版热数据实际为 2,077,698,736 bytes，另有 2,058,433,224 bytes 因预算限制放在主机映射内存；新版热数据为 4,136,131,960 bytes，因预算而未晋升的热数据为 0。

整个响应库仍为 7,025,063,556 bytes；部分续接索引继续采用原有主机映射策略，不能称为全部响应库都进入了显存。原响应文件、表 ID、全部行、解码值、逐路径材料/边界处理、横向电子沉积和严格校验均保留。

电子任务队列保持 576 MiB、128 bytes/任务、容量 4,718,592；chunk262144、lanes16384、group32 和 tiered_decoded 均不变。所有 GPU 计分固定 FP32 ON、FP64 OFF。Water_75eV 参考及 stopping scale 1.0 不变。

两组 2M 确认中，患者次级队列最终数量最大 145,753，铜级联最大 16,812；铜 primary-child 任务最大 941,046。该子队列按 `min(secondary_queue_capacity, 2*histories)` 分配，在测试的 1M/2M 规模下容量不变。所有队列原有的溢出拒绝机制保留，未丢弃任务。

容量调整仅作用于这份 CT 预设，不改变全局 32M 默认值、水模体、质子/碳 broadbeam 预设。性能与容量证据覆盖当前源/CT、最高每次 2M 的运行；大统计累计可沿用 2M 分批，不将本轮结果外推为任意单次粒子数的容量保证。

## 实测性能

种子 100250201 按原版→新版，100250202 按新版→原版，各 2M 历史。每臂合计 4M。普通 GPU 计时串行执行，与编译和 NCU 分离；完整耗时包括初始化、输运和输出。

| 指标 | 原版平均耗时 | 新版平均耗时 | 吞吐提升 |
|---|---:|---:|---:|
| 电子队列 | 8.4012 s | 4.8385 s | +73.63% |
| 输运 | 25.3247 s | 21.7332 s | +16.53% |
| 完整运行 | 47.5848 s | 43.2771 s | +9.95% |

两对完整吞吐分别 +9.3407% / +10.5665%；电子吞吐分别 +73.1396% / +74.1220%。电子耗时减少约 42.41%，与吞吐提升的分母不同。

每秒一次的 `nvidia-smi` 采样中，2M 运行峰值显存原版 10235 MiB、新版 9681 MiB，减少 554 MiB。该数值是采样峰值，不是每次分配的精确瞬时高水位；独立内存追踪器不包含响应库单独分配，不能只凭其数字估计总显存。

1M 筛选另有“仅缩小次级队列、保留 2 GiB 热预算”的独立对照：电子 4.1755 s，原版前后均值 4.1847 s，未显示实质改善；同时增加热预算后为 2.3994 s。对应完整运行 34.8049 / 35.2054 / 32.6025 s。这支持响应记录驻留位置是电子核收益的主要来源，不把少预留空队列本身称为电子输运算法加速。

## 剂量与完整性

两组主确认的离散输运/EM 审计、电子 tasks/advances/source restarts/boundary restarts/peak tasks 完全一致。质量、能量和零溢出检查全部通过。

- 剂量最大相对 L1：5.073e-8。
- 非零体素最大局部相对变化：1.298e-6，即 **0.000130%**。
- 峰谷 ROI 最大相对变化：1.187e-9。
- 最大相对能量残差：3.437e-7。
- 没有新增或丢失非零剂量体素。

交付回归另外完成：group1 的 16,384 历史产生 4,470,899 个电子任务、29,516,293 次推进；关闭延后出生采样的 100k 历史产生 846,358 个任务、5,477,564 次推进。两组均与原配置精确匹配，零溢出，最大局部剂量变化分别 3.212e-7 / 3.527e-7。结果见 `fit_delivery_checks.json`。本轮只改这份 CT 配置，没有另跑水模体或 broadbeam 回归。

这些是既有研究模型的实现/配置等价性检查。本轮未重跑 TOPAS 或 gamma，也未解除 group32 和材料电子响应原有验证限制。

## 硬件剖析

同一正式二进制，300k 历史、种子 100230001，选第一个电子 launch（对应首个 262144 历史批次）；原版复用上一轮同二进制报告。以下是单次 launch 诊断，不是整程平均；速度结论使用上面的普通配对计时。

| NCU 指标 | 原配置 | 新配置 |
|---|---:|---:|
| 平均活跃线程/warp | 8.26 | 8.27 |
| 每条已发射 warp 指令间隔 | 72.57 cycles | 42.01 cycles |
| Long-scoreboard 等待 | 56.2 cycles | 22.9 cycles |
| Long-scoreboard 占指令间隔 | 77.5% | 54.4% |
| Eligible warps/scheduler | 0.03 | 0.05 |
| L2 命中率 | 85.46% | 85.85% |
| DRAM throughput | 16.10% | 29.36% |

活跃线程基本不变，访存依赖等待明显减少，与响应记录驻留设备内存后的电子耗时改善一致。寄存器仍为 255，正式内核机器码未改；不能声称消除了发散或寄存器溢出。NCU 经已有 ps/sudo 授权执行，没有修改全局驱动权限。

## 未采用的实验

实验前搜索 `failed.md`；本轮三条被拒路线及重试条件已追加到台账。隔离源码全部保留，没有覆盖正式源码。

1. **合并子代校验和选择遍历**：在完整校验过程中记住选中游标，消除第二次遍历。GCC/项目 Clang 分别通过整数能量与随机小数能量两套各 2,737,280 个对照，覆盖电子/光子、零能量分支及选中后仍有坏子代的拒绝。1M 前后基线平均电子 4.1498 s，候选 4.1571 s；完整 34.9295→35.5059 s。无收益，不采用。静态寄存器仍 255，栈 2688→2672 B，不能据此宣称运行更快。
2. **延后 DDA 格间距除法**：只在真正跨格并继续处于同材料/密度时计算该方向的格间距；保留原来的精确格面归属和加法递推。两编译器各通过 1.2M 几何全字段对照。1M 电子 4.1893→4.2300 s，完整 34.8298→35.0050 s；资源仍 255 寄存器/2688 B 栈，无收益，不采用。
3. **保留 32M 次级队列，仅将热预算改为 4 GiB**：初始化后续分配发生 `std::bad_alloc`，没有有效输运、剂量或吞吐。初始估算遗漏了后续缓冲区，失败日志保留。完整运行显存监测随后明确了空间限制，才建立带独立队列对照的 8M/4GiB 新候选；未重复原样失败配置，也未接受失败启动计时。

前两项 GPU 筛选、队列尾部、剂量和能量检查均通过，但性能不支持采用。它们与最终显存配置优化分开测试，收益不混合。
