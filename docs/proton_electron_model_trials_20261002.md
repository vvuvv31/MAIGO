# Proton minibeam 电子包替代试验

按用户调整，后续以已有良好匹配的 **proton CT minibeam** 为首个验收场景。Carbon 的扩展训练暂不增加；已有失败结果及通用电子计分工具保留。最终目标仍是找到约 1% 额外剂量变化内、实际减少加载和输运时间的方案，并在 README 给出经过验证的方法与引用。

当前已交付 **离线紧凑运行包 C**：1M 新进程筛选吞吐 +61.0%，两组反向原生 2×2M 完整进程吞吐 +25.2%，运行时 bank 7.03→6.09 GB；配对最大逐体素剂量变化约 0.000171%。源码与 `build/carbon_mc` 已同步，已按用户要求在 proton CT minibeam 默认配置中指定派生包，无需额外环境变量。下文保留 A/B 的未采用结果、C 的验收证据及使用命令。

## 固定基线与标准

- 当前 `config/proton_ct_minibeam.yaml`：170 MeV，肺 CT，0.5 mm 狭缝/3.6 mm 节距，group32，预解码响应、保留 bank、多批次单进程；GPU 剂量 FP32 ON、FP64 OFF。各候选的主粒子输运、铜/空气、核反应、电子产生及 group 设置与配对基线一致。
- 已有 GPU/TOPAS 各 200M 是外部参考锚点，而非最新源码二进制：local 1/2/3% /0.2 mm 分别 92.1627/96.4155/97.9345%，3%/0 mm 为 89.2961%。沿用其二维 BODY 内 y 平均图、低剂量阈值和 ROI 定义，不能称为三维 gamma。见[参考报告](proton_ct_200m_gamma_0p2mm_20261001.md)。当前代码先与当前配对基线比较，再对既有 TOPAS 参考；不默认历史二进制与最新代码完全等价。
- 约 1% 指候选相对现有电子模型的**额外**峰谷剂量变化，另查局部剖面、逐点差异、gamma 变化和多种子统计。既有 GPU/TOPAS 偏差独立报告；不以拟合 TOPAS 或全局剂量缩放抵消候选误差。
- 计时区分冷启动、驻留内存、电子核、连续批次总吞吐，并比较达到同等统计精度的时间；group32 粒子数相同不自动意味着不同抽样器方差相同。

## 首先处理什么

1. 从 **当前 proton 包**核对材料、密度、父质子能量、电子能量和角度条件及能量份额。优先构造保留现有包分布的紧凑表示，先量化表示误差，避免同时更换电子参考物理和表示。
2. 研究均匀区域内可直接抽样的联合空间沉积分布，保留横向位移、能量长尾，以及现有同材料光子回放与缺覆盖记账。区域是否允许使用该分布必须有覆盖整个相关路径范围的材料/密度证据；只验证起点/终点材料相同不够。
3. 靠近异质界面或无覆盖处保留现有逐路径处理。不能从深度或平均电子贡献直接决定局部沉积，也不能使用水响应替换 CT 材料响应。先离线检验，再隔离 GPU 开关、配对剂量和等精度计时，最后才考虑默认采用。

上述是待检验方案，不是已经实现的 CT 加速路径。球形宏步模型在匹配名义步长后仍有 1.7–2.6% 峰谷偏差，不能直接移植为已通过的 proton 方法；见[失败诊断](electron_macro_trials_20261002.md)。

方法背景：[MMC](https://doi.org/10.1088/0031-9155/37/1/007)、[自适应 MMC](https://doi.org/10.1186/s13014-019-1362-5)、[DPM](https://doi.org/10.1088/0031-9155/45/8/315)；这些论文支持研究方向，不替代本项目亚毫米峰谷验收。

## 已完成的准备

`benchmark/electron_response_model/proton_inventory.py` 已生成 `out/proton_electron_model_20261002/inventory.json`，固定当前配置/index 哈希并统计包文件与代表性材料的原始电子出生谱。它读取实际 proton 提取记录、验证 SHA、核实 primary 为 proton；不将 carbon 记录改标签使用。

170 MeV 质子对自由静止电子的最大转移能量约 **0.403 MeV**，因此此前 0.65 MeV 单电子诊断不是该质子源的代表性上限。包覆盖至 250 MeV 质子，不能为单个 170 MeV 场景删除其他能量覆盖。提取谱不等于实际 CT 的剂量加权访问谱，后者仍须采集。

通用的原生逐历史计分器已在独立 2×1000 电子 smoke 中验证：完整输运记录排序后与原二进制逐字节相同，逐历史 36-bin 剖面最大差 1.11e-16 MeV，能量账一致。这个工具可在需要独立原生参考时复用；其通过不代表任何替代响应模型已通过剂量验收。证据 `out/electron_history_profile_smoke_check_20261002.json`。


## 2026-10-02 首轮实现试验（隔离候选）

先试无需改变剂量分布的实现路线，避免同时改变物理与表示。已搜索 `failed.md`；不重复单步终止响应缓存、均匀 x-run 几何捷径或子代单次遍历。

候选 A 在加载时对每条原始记录执行原有完整 replay 校验，保存一个 8-byte 的已验证子代能量和；GPU 保留动态位置/能量、材料边界及 lineage 检查，省去 prepare 阶段对下一步/子代不可变内容的重复读取。负标记仍走原校验逻辑；原始 SHA、出生索引和谱系校验未删。相对旧版会增加元数据及启动计算，必须用实际计时判断是否有净收益。候选代码、原文件、构建参数和测试均隔离在 `out/proton_electron_prevalidated_20261002/`；该独立试验阶段未替换正式代码，后续组件由候选 C 接入。

GCC 和项目 Clang 各对所有 17,475,439 条记录的 raw/候选 replay 进行逐字段位比较，状态、能量、位置、方向及索引结果一致。GPU 配对及连续批次实验已完成，结果见下节；这些位比较本身不代表速度收益或新的 TOPAS 验收。

独立的候选 B 可行性检查发现：原包原始记录中 e- 13,379,138 条、gamma 2,535 条、父质子 4,093,766 条。父质子记录用于离线出生索引和校验；研究在完成这些处理后，从运行时图中移除父质子记录并统一重映射所有电子索引。必须保留每个电子/光子状态、next/child 关系、出生 CDF、能量 crossing 候选顺序；未证明一致或无运行时访问前不能交付。`native/packed_electron_graph.hpp` 是离线研究原型；其实现先接入隔离候选，随后由 C 与离线格式一起接入主源码。


候选 B 的完整离线图检查已完成：13,381,673 条电子/光子记录全部保留，逐字段位值及 next/child 身份和子代顺序一致（仅统一改变行索引）。核心 decoded+next/child 图从 4,365,706,592 bytes 降到 3,323,353,320 bytes，减少 1,042,353,272 bytes（23.876%）。该数字不含其他 bank 数组，也不是磁盘包、启动或 GPU 吞吐的测量收益。运行时集成已写入隔离候选；全包出生/CDF/crossing 检查和百万粒子配对剂量均已通过，结果见下节。证据 `out/proton_electron_prevalidated_20261002/{packed_graph_check,packed_graph_summary}.json`。


### 候选 A 的实测结果

百万粒子筛选（原版前后夹测、同候选 OFF 控制）电子核均值 2.3960→1.9694 s，输运 10.9596→10.5199 s；完整运行 32.9134→33.2641 s，首次加载的额外工作抵消了收益。同候选 OFF 电子核 2.3990 s，支持测得变化来自启用预校验，而非仅重编译差异。

另做两个独立种子、反向运行顺序的原生连续批次确认：每进程 2 批×2M，每臂共 8M。合计电子核 19.3827→15.8664 s，吞吐 **+22.16%**；输运吞吐 **+3.71%**；每个进程第二批（已驻留 bank）的完整吞吐 **+3.71%**。含首次加载的整个进程吞吐仅 **+0.78%**，两对分别 +0.528%/+1.032%。所有批次只加载一次 bank。

全部离散输运/EM/电子任务及步进计数一致，质量、能量、零溢出检查通过。所有非零体素的最大相对变化 1.6255e-6（0.0001626%），分深度峰/谷最大相对变化 1.3140e-9；最大能量残差 3.403e-7。这是既有物理模型的配对实现验证，没有重新宣称 TOPAS gamma 验收。

预校验数组新增 139,803,512 bytes，运行时 bank 总量 7,025,063,556→7,164,867,572 bytes；现有 4GiB 热预算下有 48,823,008 bytes bulk 留在映射主存。**不单独切换默认配置**：电子核收益真实，但单批启动成本与整个进程收益不支持直接全局采用。保留隔离候选作为后续组合的组件。

证据 `out/proton_electron_prevalidated_20261002/{screen_summary,continuous_summary,continuous}.json`；源码、补丁、原/新二进制、两编译器全包检查、逐批剂量/审计及温度/时钟记录均保留。

### 当前默认使用方式

默认 `config/proton_ct_minibeam.yaml` 已设置：

```yaml
material_electron_packed_directory: data/ct_electron/proton_packed
```

此配置项同时选择 packed graph、预校验证书和离线包加载，并优先于旧实验环境变量。路径加入 retained-bank 的缓存身份；新路径不能复用先前目录的 bank。proton water、carbon 及 broadbeam 预设不设置此项。`broadbeam_fast` 配置展开会移除这项无关输入。

首次部署或算法更新后生成当前指纹的默认包：

```bash
bash scripts/build.sh
python3 scripts/prepare_material_electron.py \
  --index data/ct_electron/proton/index.json \
  --cache data/ct_electron/proton_packed --packed
```

随后普通入口和多批次入口无需环境变量：

```bash
bash scripts/run.sh proton_ct_minibeam \
  --histories-per-batch 2000000 --batch-count 2 \
  --batch-output out/proton_packed_run
```

### 当前电子处理方法

这是有限原始轨迹库的能量包回放，尚未采用参数化电子分布或公式替代整包。

1. **离线准备**：原始响应、轨迹 SHA、primary 出生能量分配与谱系校验后，保留所有电子/光子状态及原数值。完成出生 CDF、能量 crossing、next/child 索引，去掉仅用于离线建索引的父质子行，并预存每行已验证的子代能量和。横向位置/方向、子代关联和候选顺序均保留。
2. **出生与 group32**：主质子已采样的总电离能损按当前材料、密度及质子能量对应的出生能量份额划分。电子份额形成带权能量包，出生状态按能量加权 CDF 抽样。每组至多 32 个源任务通过按权重的 reservoir 抽样保留一个代表，把组总权重交给它；不是把32条电子轨迹全部逐条模拟。
3. **电子及 cascade**：回放记录的输运段，检查动态几何和能量。按当前段沉积、母电子剩余能量及各子代出生能量选择一个结果：沉积，继续母粒子，或进入一个电子/光子子代。包的统计权重随这条分支保留，不把全部子代展开成显式树；被选中的电子/光子保留相应位置、方向与能量关联。
4. **界面及有限轨迹续接**：对 CT 材料边界截断输运段。电子跨材料或源记录耗尽时，按当前材料/密度与连续动能的 crossing 条件重新抽样续接。记录覆盖内的光子可回放；无光子续接覆盖时单独记入缺覆盖能量项，不假作局部沉积。
5. **剂量与范围**：保留空间沉积和横向扩散，使用 FP32 剂量原子累加。这套材料响应目前主要处理主粒子电离能损；核反应产生的带电次级粒子的电子损失仍走原来的局部处理，不能称为所有次级电子的完整显式输运。

此次默认切换只更改加载和不可变数据的预处理，group32、上述抽样规则、主输运参数和电子响应分布均未调整。
