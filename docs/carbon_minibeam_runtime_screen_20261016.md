## 大批次边界

尝试2080Ti每批20M和A6000每批30M时，两卡都因默认8M铜直接子粒子队列溢出而被拒绝；没有接受剂量或吞吐。history_chunk_size只限制活跃primary池，不会自动分批排空整个field出生的铜子粒子队列。增大单批粒子数不能作为当前代码的通用提速方式；后续大计划应使用可完整通过审计的批次，或单独重构队列排空/容量管理。

## 后续重点

目前患者主粒子+患者次级占2080Ti约60.3%。假想两者都减半，按本轮成本仅约96.7k/s，仍未达到100k/s；这只是Amdahl上界算例，不是实现承诺。下一轮应定位native单步的涨落/Urban/continuous26动态成本，或针对铜后续级联采用保留状态的任务调度。重复本轮账本合并、空间分块、旧tail阈值/几何guard失败方案缺少依据。
