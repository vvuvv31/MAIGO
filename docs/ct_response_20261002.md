# CT 电子响应预解码优化（2026-10-02）

在 RTX 2080 Ti 上，当前 proton CT minibeam 的两组独立、反向顺序 200 万粒子配对确认：完整吞吐提高 **12.95%**，输运吞吐提高 **26.07%**。正式配置改为 `material_electron_response_cache_policy: tiered_decoded`，仍使用262144批次、group32、576MiB队列和2048MiB热数据预算。所有构建均为FP32剂量，FP64剂量关闭。

## 实现和边界

原来每次电子回放都从312-byte TOPAS V4字节记录解码位置、方向、能量和谱系，并重复检查不可变字段。现在加载已校验的原始文件时，使用原解码器生成232-byte `ElectronContinuationStep`，以此替换GPU/映射内存中的字节副本。

- 保留全部记录、原始行号、表编号、每个字段的位值，以及无效记录的状态；没有截断轨迹、量化能量、修改RNG或增加采样近似。
- 原始文件、SHA256、CPU谱系链接、出生索引和能量穿越索引的验证保持不变。
- GPU每步仍检查粒子类别、谱系、子粒子位置与能量、后继位置与方向、能量闭合及CT边界；证书身份检查包括新的decoded指针。
- 原始byte路径保留。`tiered_decoded`用于CT packet路径；既有非minibeam物理和水响应模型保持不变，水参考仍是Water_75eV。
- 索引、任务和剂量类型不变：任务128bytes，队列容量4718592。初始化略增，电子回放成本下降。

响应库总驻留量（显存加映射主存）从8423098172降到7025063556bytes，减少约1.30GiB。热显存保持约1.94GiB，因此不能把这个数字解释为节省了1.30GiB显存。电子核仍为255寄存器，静态stack从2848降到2640bytes。

## 正确性

GCC和项目Clang分别逐位比较全部17475439条记录的raw/decoded replay，包含状态、谱系、子粒子范围和能量残差。GPU独立2M确认的全部离散输运/EM审计、电子tasks/advances/restarts一致。

- 最大剂量相对L1：5.0761e-8。
- 全部非零体素最大局部相对变化：8.6145e-7，即0.0000861%；没有新增或丢失非零体素。
- 分深度峰/谷ROI最大相对变化：1.0735e-9。
- 最大运行相对能量残差：3.4149e-7；队列溢出为0。

这些是对既有模型的实现等价验证，没有重新跑TOPAS，也不改变现有CT group32研究精度限制。

## 其他场景回归

Group1的16384粒子高水位用例：4385915tasks、28897258advances和7024423boundary restarts完全一致，原容量下零溢出。电子耗时4.26976->2.20006s；该小样本用于容量/正确性检查，不作为端到端提速结论。

水minibeam的1M对照、完整质子CT part_01计划12531500粒子和碳CT6481909粒子对照均完成。所有离散审计一致，剂量相对L1不超过1.823e-7。水的单对计时受到初始化影响，不据此宣称水吞吐收益。

质子broadbeam三组配对：完整均值30.17665->30.20007s（吞吐−0.08%），输运27.33005->27.43836s（−0.39%）。碳两组完整38.27077->37.75082s，输运35.33920->35.28386s；冷/热启动及温度差异明显，不把单次初始化差异作为新加速结论。两种broadbeam主核的规范化SASS指令及资源完全相同。

碳的原始 `unvalidated_electron_joint_response` 失败和exit1保留，所有碳计时仅作诊断，其余能量/队列/输运检查通过。比较器修正了一个类型误判：`primary_selected_energy_mismatch_sum`是C++ double，302563->302562.5的相对变化1.65255e-6保留strict1e-6失败标记，investigation1e-4通过；不再将其JSON整数写法当作事件计数。没有重采样或降低物理质量门槛。

同进程两批各1M（种子100200103/100200104）已使用安装后的正式二进制验证，缓存命中1次，所有批次质量/能量/队列检查通过。首批与独立运行的整数审计一致，局部最大相对变化8.8283e-7；两批耗时35.6019/15.1159s仅用于记录缓存执行行为，不作为独立配对加速结论。证据`delivery_batch/`和`batch_checks.json`。
