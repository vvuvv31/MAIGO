# C12电子包进一步压缩：全库只读可行性检查

本轮没有更改默认代码、二进制、电子包或物理模型。已搜索failed.md；以下是当前v4表示上的新布局候选，不重试已失败的球形宏响应、参数化分布或串行zstd加载提速。证据及可重跑脚本：`out/carbon_compact_feasibility_20261003/`。

## 实际占用

全部63表数组合计45.9226GiB：动态步记录25.8764GiB、有序候选crossings11.2187GiB、轨迹字典3.3790GiB；next、child_offsets及child-energy证明各1.4376GiB，出生样本1.0691GiB，其余约0.067GiB。磁盘zstd不会减小这些运行数组。

## 两阶段无损候选

1. 稠密候选桶使用位图+每512行uint32前缀计数，稀疏桶保留原uint32数组。原rank经select恢复同一行号，不改能量区间、候选顺序、RNG或回退遍历。已经完整扫描所有存储序列，确认每个非空共享桶的候选严格递增且不越界。按实际行数和桶密度逐表计算，含前缀计数及每桶16B描述符，索引预计11.2187→1.7944GiB。GPU查找成本尚未测量；不能据空间估计宣称提速。
2. next、child_offsets、children逐表改uint32，使用UINT32_MAX结束标记。所有表行数、子索引数量和实测offset均在范围内，约省1.4706GiB。未来超范围表必须明确拒绝或保留64位表示，不能截断。

合计数组预计45.9226→35.0278GiB。仅为表示字节数估计，尚未实现运行时和端到端验收。

## 端点共享

完整扫描192,948,558条EM记录的136,257,785条next关联，每条当前步post位置/方向/能量的7个double，均与下一步pre字段逐位相等。没有使用浮点容差，也没有假定相邻行就是next；实际有26,339条非相邻next。

可将7-double端点拆成56B节点，步记录用两个32位端点编号。每条合格关联少存一份56B端点，所有行多8B编号；此明确布局净省6,086,847,496B（5.6688GiB）。与前两项合计数组约29.3590GiB。需要制包验证唯一关联/重建映射、字段位值、GPU读取开销和剂量审计；当前扫描不是最终布局验收。

## 后续空间与边界

仅8,858,017行（4.5909%）有子粒子，184,090,541行没有子粒子且child-energy证明严格为正零。可进一步研究稀疏子链/能量证明；需计入位图、rank和异常项查找开销，本轮不为其承诺交付体积。保留全部电子/光子分支。

若目标为8–16GiB，以上已量化的无损布局仍不足：需更深入字典/数值编码，或重新设计按需驻留及调度。按需跨材料访问可能引入PCIe/磁盘等待。浮点量化、轨迹简化、拟合响应属于另需独立验证的近似，必须保持已授权约1%峰谷局部剂量差异门槛，不能直接将电子换成局部沉积。

建议先实现候选索引+32位图，再做端点共享；每项先全库字段/候选顺序检查，再FP32 GPU同种子、能量/溢出/峰谷检查和驻留吞吐对照。避免在共享热路径重复引入proton分支开销，上一轮已有proton电子核退化的证据。
