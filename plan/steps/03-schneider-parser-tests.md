# Step 03 — Lock parser and HU boundary semantics with tests

## Objective

Make it impossible for a fast implementation to appear correct while shifting a section boundary, skipping a row, normalizing bad input, or confusing element order.

## Required tests

Add focused C++ tests in the existing test target. Use small temporary TOPAS-format files where malformed cases are needed.

1. Golden file: load `data/HUtoMaterialSchneider.txt`; assert 13 names/Z values in file order and 25 rows.
2. Assert all 26 exact HU edges.
3. For every internal edge `b`, test `nextafter(b, -inf)`, `b`, and `nextafter(b, +inf)`. At `b`, selection must move to the new `[b,next)` section.
4. Check representative HU values and density against independently listed expected constants, not values generated by the parser under test.
5. Assert selected mass fractions for air, lung-like, soft-tissue, calcium-rich, and titanium sections.
6. Reject missing `SchneiderElements`, unsupported/duplicate element, 12/14 elements, missing/duplicate material row, wrong vector count, negative/NaN weight, row sum outside tolerance, non-monotonic edges, and inconsistent density correction counts.
7. Round-trip a synthetic 25-voxel `CtGrid`; verify only density and section ID are stored per voxel.

## Test quality rules

- A test that only checks `no throw` is insufficient.
- Expected boundaries/weights must be literal fixtures or a separately reviewed golden JSON; do not parse the same input with the same helper to generate expectations.
- Error tests must check informative message fragments.

## Acceptance

All focused tests pass in a clean build, malformed cases fail for the intended reason, full existing CPU tests pass, and `git diff --check` is clean.
